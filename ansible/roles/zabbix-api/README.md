# Роль: zabbix-api

## Описание
Эта роль автоматически регистрирует хосты в Zabbix Server через API.
Она использует прямые HTTP-запросы (модуль `ansible.builtin.uri`) вместо стандартного модуля 
`community.zabbix.zabbix_host`.

## ⚠️ Важные примечания (Почему всё так сложно?)

1. **Обход бага `httpapi`**: 
   В процессе разработки выяснилось, что модуль `community.zabbix.zabbix_host` (в связке с плагином `httpapi`) 
   некорректно склеивает URL (добавляет двойной слэш `//api_jsonrpc.php`). Из-за этого Nginx возвращал 
   ошибку `404 Not Found`. Поэтому было принято решение отказаться от стандартного модуля и 
   реализовать прямые POST-запросы через `ansible.builtin.uri`. Это надежнее и прозрачнее.

2. **Проблема `127.0.0.1`**: 
   При первой инициализации Zabbix Server в Docker автоматически создает хост "Zabbix server" с 
   локальным IP `127.0.0.1`. Наша роль умеет **обновлять** этот хост, принудительно прописывая 
   ему внешний IP-адрес виртуальной машины (например, `172.16.0.200`), чтобы мониторинг работал корректно.

3. **Хардкод IP**: 
   В учебных целях IP-адреса хостов прописаны в переменной `zabbix_api_hosts` (в `defaults/main.yml`). 
   В продакшене эти данные должны динамически подтягиваться из Terraform (файлы `.tfstate` или `.env`).

## Переменные
*   `zabbix_api_host_group` - Имя группы хостов в Zabbix.
*   `zabbix_api_template` - Имя шаблона (например, `Linux by Zabbix agent`).
*   `zabbix_api_agent_port` - Порт агента (по умолчанию 10050).
*   `zabbix_api_hosts` - Список словарей `{name, ip}` для регистрации (задается в `defaults/main.yml`).
*   `vault_zabbix_admin_password` - Пароль администратора Zabbix (хранится в Ansible Vault).

## Как это работает
1. Авторизация в API (`user.login`) и получение токена.
2. Получение ID группы и шаблона.
3. Проверка существующих хостов (`host.get`). Формирование списка `existing_host_names`.
4. Обновление существующих хостов (`host.update`) — исправляет `127.0.0.1` на правильный IP.
5. Создание новых хостов (`host.create`), которых еще нет в Zabbix.
